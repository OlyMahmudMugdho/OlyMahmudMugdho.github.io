# TCP এবং নির্ভরযোগ্য Byte Stream কীভাবে কাজ করে

Express, Gin, বা Go-এর `net/http` ব্যবহার করলে আমরা সাধারণত শুধু request আর response অবজেক্ট নিয়ে কাজ করি। নিচের ট্রান্সপোর্ট লেয়ারে বাইটগুলো কীভাবে যাচ্ছে, তা নিয়ে ভাবতে হয় না। এই সিরিজে আমি Go দিয়ে শুধু raw TCP socket ব্যবহার করে Ant নামে একটা ছোট HTTP সার্ভার বানাব। সার্ভারের কোডে যাওয়ার আগে TCP আসলে কী সুবিধা দেয়, সেটা বুঝে নেওয়া দরকার।

## TCP কেন দরকার

নেটওয়ার্ক লেয়ারে IP ডেটাকে ছোট ছোট packet-এ ভাগ করে রাউটারের মধ্য দিয়ে পাঠায়। IP হলো best-effort। রাউটারে চাপ বেশি থাকলে packet হারিয়ে যেতে পারে, ভিন্ন পথ দিয়ে এলে ক্রম এলোমেলো হতে পারে, আবার কখনো packet ডুপ্লিকেটও হতে পারে।

অ্যাপ্লিকেশনকে যদি নিজেই হারানো বা এলোমেলো packet সামলাতে হতো, তাহলে ওয়েবপেজ লোড করা বা JSON পার্স করা খুবই ঝামেলার হয়ে যেত। TCP ঠিক IP-এর ওপরে কাজ করে এবং দুইটা প্রোগ্রামের মধ্যে একটা সাজানো, নির্ভরযোগ্য, দ্বিমুখী byte stream দেয়। এক পাশ থেকে `"Hello World"` লিখলে অন্য পাশ ঠিক একই ক্রমে `"Hello World"` পাবে, অথবা কানেকশন বিচ্ছিন্ন হলে error পাবে।

## IP Address এবং Port

IP address (যেমন `127.0.0.1` বা `93.184.216.34`) নেটওয়ার্কে একটা নির্দিষ্ট মেশিনকে চেনায়। আর port নম্বর (যেমন `80`, `443`, বা `8080`) সেই মেশিনে চলা নির্দিষ্ট একটা প্রসেসকে চেনায়। একই মেশিনে `5432` পোর্টে PostgreSQL, `3000` পোর্টে ফ্রন্টএন্ড ডেভ সার্ভার, আর `8080` পোর্টে আমাদের Go সার্ভার একসাথে চলতে পারে।

অপারেটিং সিস্টেম প্রতিটা TCP connection-কে চারটা মান দিয়ে আলাদা করে চেনে:

```text
(Client IP, Client Port)  <======>  (Server IP, Server Port)
  127.0.0.1 : 54321                   127.0.0.1 : 8080
```

প্রতিটা নতুন কানেকশনের জন্য ক্লায়েন্টের OS একটা খালি অস্থায়ী port (ephemeral port) বেছে নেয়। এই কারণে ব্রাউজার একই সার্ভারের `443` পোর্টে একাধিক কানেকশন খুলে রাখলেও ডেটা একে অন্যের সাথে মিশে যায় না।

## Three-Way Handshake

অ্যাপ্লিকেশনের ডেটা পাঠানোর আগে ক্লায়েন্ট আর সার্ভার কানেকশন তৈরি করে এবং শুরুর sequence number ঠিক করে নেয়। এটা তিনটা packet-এ সম্পন্ন হয়:

```text
Client                                      Server
  |                                           |
  |  1. SYN (seq=x)                           |
  | ----------------------------------------> |
  |                                           |
  |  2. SYN-ACK (seq=y, ack=x+1)              |
  | <---------------------------------------- |
  |                                           |
  |  3. ACK (ack=y+1)                         |
  | ----------------------------------------> |
  |                                           |
  |======== Connection Established ===========|
```

1. ক্লায়েন্ট নিজের শুরুর sequence number `x` সহ একটা `SYN` packet পাঠায়।
2. সার্ভার `x+1` নিশ্চিত করে এবং নিজের শুরুর sequence number `y` সহ `SYN-ACK` পাঠায়।
3. ক্লায়েন্ট `y+1` নিশ্চিত করে `ACK` পাঠায়।

এই তৃতীয় packet-এর পর কানেকশন চালু হয়ে যায় এবং দুদিক থেকেই বাইট আদান-প্রদান করা যায়।

## TCP কীভাবে নির্ভরযোগ্যতা বজায় রাখে

অপারেটিং সিস্টেমের নেটওয়ার্ক স্ট্যাক কয়েকটা মেকানিজমের মাধ্যমে ডেটা নির্ভরযোগ্য রাখে:

- Sequence number প্রতিটা বাইটের অবস্থান ট্র্যাক করে। packet 1-এর আগে packet 2 চলে এলে OS সেটিকে receive buffer-এ ধরে রাখে এবং packet 1 আসার পর সাজিয়ে প্রোগ্রামের হাতে দেয়।
- Acknowledgment (ACK) দিয়ে রিসিভার জানায় সে কতটুকু ডেটা পেয়েছে। নির্দিষ্ট সময়ের মধ্যে ACK না এলে সেন্ডার ওই ডেটা আবার পাঠায়।
- Flow control-এ রিসিভার জানিয়ে দেয় তার বাফারে কতটুকু জায়গা খালি আছে (receive window), যাতে দ্রুতগতির সেন্ডার ধীরগতির রিসিভারকে চাপের মুখে না ফেলে।
- Congestion control নেটওয়ার্কে packet drop দেখলে পাঠানোর গতি কমিয়ে দেয়।

যেহেতু kernel এই সবকিছু সামলায়, আমাদের Go কোডে শুধু `net.Listener` আর `net.Conn`-এর মতো socket API ব্যবহার করলেই চলে।

## TCP হলো Byte Stream

HTTP সার্ভার লেখার সময় একটা ব্যাপার মাথায় রাখা জরুরি: TCP-র নিজের কোনো মেসেজ সীমানা (message boundary) নেই।

ধরুন ক্লায়েন্ট প্রথমে `"GET / HTTP/1.1\r\n"` আর তারপর `"Host: localhost\r\n\r\n"` পাঠাল। নেটওয়ার্কের অবস্থার ওপর নির্ভর করে সার্ভারের `Read()` কলে পুরোটা একসাথে আসতে পারে, আবার প্রথম কলে `"GET / HT"` আর পরের কলে বাকি অংশ আসতে পারে। একই কানেকশনে পরপর দুটো request এলে দুটোই এক `Read()` কলে চলে আসতে পারে।

যেহেতু TCP শুধু অবিচ্ছিন্ন বাইট প্রবাহ দেয়, তাই ওপরে চলা প্রোটোকলকেই ঠিক করতে হয় একটা মেসেজ কোথায় শেষ হয়ে পরেরটা শুরু হচ্ছে। HTTP এই কাজটা করে `\r\n\r\n` আর `Content-Length`-এর মতো হেডার দিয়ে।

## Connection বন্ধ করা

ডেটা পাঠানো শেষ হলে দুপক্ষ `FIN` packet দিয়ে কানেকশন বন্ধ করে:

```text
Client                                      Server
  |  FIN                                      |
  | ----------------------------------------> |
  |  ACK                                      |
  | <---------------------------------------- |
  |  FIN                                      |
  | <---------------------------------------- |
  |  ACK                                      |
  | ----------------------------------------> |
```

Go-তে `conn.Close()` কল করলে ওই socket-এর জন্য এই বন্ধ হওয়ার প্রক্রিয়া শুরু হয়।

এর পরের লেখায় আমরা দেখব এই TCP stream-এর ভেতর দিয়ে চলা HTTP/1.1-এর টেক্সট ফরম্যাট কেমন হয়।
